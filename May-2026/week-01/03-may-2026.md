Objective:

**The SplitText Detour and the Canonical FOUC Fix:** Mid-session a `SplitText` word-by-word reveal was attempted on the hero headline, the plugin registered, words split with `mask: 'words'` and animated with a 0.05-second stagger on `yPercent`. The user reloaded and reported the headline was completely invisible. Root-cause analysis identified a hard constraint in the CSS specification: the `gx-font-gradient-light` utility paints a `linear-gradient` background on the parent span and clips it to the text glyphs via `background-clip: text` with `color: transparent`, but `background-clip: text` only clips the element's own background and child spans inherit `color: transparent` without inheriting any background to clip from. SplitText's per-word span wrappers therefore rendered as transparent text on no background. The same reload also surfaced a separate flash-of-unstyled-content where the headline rendered fully visible from server-side rendering, then immediately snapped to GSAP's `from`-state (hidden) and animated back in, producing three perceived states where there should have been two. SplitText was reverted in favour of the original single-block fade-up, and `motion-safe:invisible` was added to every animated element so the Tailwind motion-safe variant generates `visibility: hidden` for users without reduced-motion preferences, server-side rendering paints the from-state correctly and reduced-motion users see content immediately because the class is gated. The pattern became the canonical FOUC fix applied to every section that followed.

**CustomScrollbar Six-Bug Saga Across Four Iterative Commits:** The custom scrollbar component produced the most diagnostically interesting arc of the session, with six distinct bugs surfacing across four iterative fix commits. Bug one was a silent typo where a missing space had collapsed two utilities into one non-class (`z-9999nsition-opacity` instead of `z-[9999] transition-opacity duration-300`), causing the JIT compiler to silently drop both the z-index and the opacity transition so the scrollbar popped in and out instead of fading. Bug two was a thumb-click teleport caused by event bubbling, where the track's `onClick` handler fired after the thumb's `onMouseDown` released because clicks bubble from child to parent, resolved by guarding `handleTrackClick` with `if (e.target !== e.currentTarget) return`. Bug three was a drag-grab teleport where the drag-move handler mapped cursor's absolute viewport-Y to scroll percentage rather than maintaining the grab-point offset within the thumb, causing the scroll to snap to the cursor's absolute position rather than tracking native-scrollbar behaviour. The fix captured `grabOffset = e.clientY - thumbRect.top` at mousedown and computed `thumbTop = moveEvent.clientY - grabOffset` throughout the drag. Bug four was a flash-of-unstyled-content where the native scrollbar appeared briefly on every page load because the suppression CSS lived in a `<style jsx global>` block gated behind `isMounted`, meaning it could not apply until after JavaScript hydration; the fix moved the suppression rules into `globals.css` where the linked stylesheet loads before any JavaScript runs, using the higher-specificity selector `html::-webkit-scrollbar { display: none }` to leave styled scrollbars on inner scrollable containers intact. Bug five was a drag-lag where the page-level `scroll-behavior: smooth` was animating every programmatic `window.scrollTo` over roughly 300 milliseconds and the thumb's visual position update was waiting on a one-frame `requestAnimationFrame` cycle; the fix used `behavior: 'instant'` to bypass the smooth-scroll CSS and wrote the thumb's `top` directly during drag so the visual position matched the cursor at 60 frames per second. Bug six was a `transition-all duration-200` utility on the thumb that was animating every transitionable property including `top` and `height` over 200 milliseconds; the original intent had been to smooth a hover gradient that was not actually transitioning because Tailwind v4 gradients use unregistered CSS custom properties that require explicit `@property` registration to interpolate. Removing the utility entirely resolved the drag lag and the hover became acceptably instant.
