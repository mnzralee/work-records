**Mesh Recovery Deferred After Validator Probe Semantic Misread Surfaces Deeper Root Cause:** The first execution block attempted a helm upgrade against the Linkerd control-plane chart with a single value override targeting the network validator connect address. The initial hypothesis from the brownfield audit was that the empty configuration default resolved to an unreachable target on the cluster network; overriding the address to the Kubernetes API server endpoint reachable from inside the cluster was expected to restore the validator handshake. The override applied and new pods spawned, but the validator continued to fail with a ten-second timeout. Reading the validator log alongside the iptables chain output revealed the actual semantic: the validator probe is not a reachability test but a redirection test, asserting that pod-egress iptables OUTPUT rules redirect arbitrary outbound TCP back to the proxy listener on the loopback interface. The deliberately unreachable default address allows the redirect rules to capture the connection and route it to the validator's own token receiver. The override broke the contract because the real API server endpoint was on the iptables RETURN list, completing a genuine TCP handshake without redirection and timing back out. The helm release rolled back to the previous clean revision, and the deeper iptables-redirect forensics filed as a carry-forward sub-session because the remaining substrate-hardening blocks ship as pure code that does not require a healthy mesh to author and verify.

**Phase Two Wave Parallel Dispatch Hits Lint-Staged Cross-Agent Sweep Contamination:** Three general-purpose agents dispatched in parallel for the two-hat key separation runbook, the continuous-integration re-enable across three repositories with husky hook portage, and the FIDO2 credential schema authoring plus architecture decision record. **Contamination Remediated via Clean Reset and Five Atomic Re-commits:** The contamination was diagnosed as a tool-chain race rather than a planned-files race: the lint-staged tool operates on the entire staged index rather than the dispatching agent's intended subset, so when the second agent committed while the third had files staged, the commit swept up unrelated work. Per the project's git-workflow rules requiring atomic self-explanatory commits, the cleanest remediation was a full reset to the remote head followed by five atomic re-commits in correct semantic order: the runbook addendum first, then the workflow rename, then the smoke-test workflow skeleton, then the WebAuthn credential model addition, then the migration generation. The git rename detection preserved the disabled-to-enabled transitions as renames rather than separate add-and-delete pairs, keeping the diff readable. The lesson was filed as an amendment to the agent-engineering rule: tool-chain serialization beyond planned-files must be enforced at commit step regardless of file-set disjointness, and any commit step in a repository with active pre-commit hooks must serialize across agents.

**Postgres Advisory Lock Primitive Lands at the Saga Entry Boundary with Clean Architecture Correction:** Block C returned in approximately ten minutes with three atomic commits and a sharp architectural correction worth recording. The dispatch brief placed a new error class in the registry-service domain layer, but the agent identified this as a Clean Architecture violation because the error is consumed by an acquire-name-lock helper in a shared core-db package that cannot import from the service without inverting the package dependency graph. The agent's resolution defined the error class in the cross-package core-errors home which already hosts a Chain-error family as precedent, then re-exported it from the service's domain errors index for narrative consistency. The lock implementation used the canonical session-scoped variant against pg_try_advisory_xact_lock with the name hash mapped to a bigint, returning a boolean and throwing the contention error on failure. The transaction-scoped semantics auto-release the lock on commit, rollback, or session crash, which aligns with the refund-path requirements where the compensator is the same pod and no second pod can be concurrently processing the same name hash. The wire-in absorbed via two extracted helpers mirroring the outbox block's discipline, growing the handler by fifty-five lines while preserving the no-any and no-ts-ignore type narrowing pattern.

**Mesh Recovery Resolved After Configuration-Pod-State Mismatch Diagnosis:** A focused continuation sub-session opened to revisit the deferred mesh-recovery block. A read-only forensics agent dispatched with a seven-step discovery mandate covering the cni invocation per pod create, the iptables-nft state inside a failing pod's network namespace via crictl plus nsenter, a healthy-pod baseline against the Postgres-primary pod, plugin standard-error capture, and a dry-run injected test pod with cluster-state-mutation gating. The agent's recommendation initially misread the evidence by claiming the cni was not invoking despite the iptables capture showing the correct PROXY_INIT chains installed. Reading the agent's own evidence carefully exposed the actual root cause: the failing pods had been created during the helm revision when the validator address was overridden to the API server endpoint, and the rollback to the prior revision had reverted the configuration map but had not restarted the pods, so the pod's environment-baked address persisted past the configuration reversion. A single rolling restart on the three control-plane deployments produced six new control-plane pods running cleanly, the proxy-injector webhook returned ready, and a rolling restart on the nine service deployments rotated all of them through the now-working webhook so each new pod received the linkerd-proxy sidecar at admission. A textbook happy-path quote call against the registry service confirmed the substrate fully alive.
