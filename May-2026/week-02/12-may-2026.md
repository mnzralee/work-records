**Production-Grade-Code Principle Crystallization on Canonical Source Resolution:** A grantRole transaction reverted with "Function does not exist" because the script's pre-flight logic called REGISTRAR_ROLE as a pure getter to read the role hash before constructing the grantRole call, but the production Diamond's AccessControlFacet exposes only grantRole, hasRole, and revokeRole functions with bytes32 arguments and does not expose role-name getter functions. The first instinct was to add a try-catch fallback that tried the live getter and on failure fell back to the off-chain keccak256 computation. The user pushed back on the fallback pattern, citing the production-grade-code rule that explicitly forbids silent fallbacks. The refactor that landed used a pure-function resolveRoleHash returning the off-chain keccak256 computation directly with no fallback, removed the now-unused getter ABI fragments and the unused EthersContract import, and lint caught the unused import on the first run which is exactly the kind of catch the production-grade-code rule expects. The crystallized principle: when production code fails because a remote source is unavailable, identify the single canonical source for each value and use that source unconditionally rather than adding try-multiple-sources-and-fall-back patterns that introduce drift potential without buying actual resilience.
