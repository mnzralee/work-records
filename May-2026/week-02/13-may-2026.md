**Bootstrap Substitution Defect and Canonical-Source Diagnosis:** The morning opened against a milestone resume task pinned to a temporary-commands pointer instructing a single bootstrap-then-smoke sequence to push the local-process milestone from ninety-five to one hundred percent. The very first probe failed when the container orchestrator complained that a required master key for the search engine was missing despite the dotted-environment file being present at the workspace root with the value written into it the prior day. Rereading the compose configuration on line eighty-six revealed the substitution syntax was reading from the default dot-env file rather than from any arbitrarily-named env file, and the bootstrap script invoked the orchestrator without the explicit env-file flag. The fix introduced a bash-array variable consolidating the orchestrator invocation with the env-file flag at the head of both the bootstrap and teardown scripts, with the array form preserving argument boundaries cleanly should the path ever contain spaces, and updated the compose header comments so every documented operator command mirrored the script's runtime behaviour. Three files were touched under three atomic commits, naming the canonical input path once rather than treating the symptom by renaming the file to the default.

**Zod Boolean Coercion Footgun and Strict envBool Helper:** Following the bootstrap fix, the smoke retry returned apparent success at the HTTP layer with a two-hundred-and-two acceptance on the role-grant transaction, but the sixty-second chain-confirmation poll came back negative. Reading the projector's startup log before retrying surfaced that the transaction-queue binding had silently fallen back to the in-memory stub despite the bootstrap explicitly setting the queue-toggle environment variable to the string false. The root cause was that the Zod coerce-boolean primitive applies JavaScript's Boolean constructor, which returns true for any non-empty string including the literal string false, and the schema-layer default masked the defect because the previous test wave had always exercised the path with the value set to true. A grep across the registrar service configurations identified three call sites bearing the same systemic defect across the chain-projector and search-service configuration modules. The production-grade remediation authored a strict envBool helper in the core-config package that accepted only the literal strings true or false using a Zod union of enum and boolean primitives with a transform clause, failing validation at startup before the service could boot in a broken state. The helper was exported from the package barrel, three call sites were refactored, and a fourteen-case regression specification including the false-string regression guard was committed to prevent future drift.
